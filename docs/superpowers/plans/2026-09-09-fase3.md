# Fase 3 — segurança e preparação para nativo

**Status: concluída e publicada em 2026-09-09.**

## Escopo implementado

- `dados.js` valida estruturas, datas, números, parcelas e listas antes da UI.
  Preserva campos desconhecidos e textos antigos sem truncamento; descarta
  elementos malformados. Não executa migração administrativa em produção.
- Novas edições: nome 120 caracteres, tópico 80, descrição/afazer 500;
  `maxlength`, trim e validação JavaScript. Taxa inválida exibe mensagem e
  preserva taxa anterior; faixa maior que zero e até 20% ao mês.
- Escape de tópicos já existia. Auditoria acrescentou defesa nos metadados
  de parcelas e teste de texto malicioso em telas, gráficos e formulários.
- Firebase 12.18.0 ESM local em `vendor/firebase`, licença incluída.
  esbuild é ferramenta de manutenção da distribuição versionada, não build
  obrigatório para abrir ou publicar a aplicação. Cache atualizado para v38.
- CSS extraído para `styles.css` e `privacidade.css`; estilos estáticos viraram
  classes. Gráficos usam classes de cor e propriedades CSS controladas por JS.
  Scripts inline já tinham sido extraídos em fases anteriores.
- CSP sem `unsafe-inline`, com scripts/estilos locais. Servidor de testes usa
  mesmos headers, acrescentando somente endpoints dos emuladores em modo explícito.
- GitHub Actions: testes unitários, rules e Playwright com Java 21, Node 22,
  permissões somente de leitura e actions fixadas por SHA.
- README atualizado para IndexedDB/Firestore, SDK local e comandos de testes.
  PRODUCT.md e cabeçalho do app já descreviam login por e-mail/Firestore.

## Validação local

- `npm test`: passou, incluindo 33 casos de rules. Rules não foram alteradas.
- `npm run test:browser`: passou com Auth/Firestore emulados: sincronização,
  persistência offline após fechar/reabrir, conta, exportações e limpeza do cache.
- Login, nova obra e gasto realizados pelos formulários reais no Chromium.
- Texto `<img src=x onerror=alert(1)>` aparece literalmente; campos acima dos
  limites são rejeitados mesmo quando preenchidos diretamente pelo JavaScript.
- SDK real inicializa sem rede externa e reabre offline usando service worker.
- Layout inspecionado em 414px e 1440px, temas claro e escuro.

## Limites e acompanhamento

- Testes locais usam Chromium e emuladores. iPhone físico e ponte Capacitor
  continuam na Fase 4; não foram certificados neste trabalho.
- Atualizações compatíveis de dependências eliminaram alertas altos encontrados
  pelo npm audit. Restam alertas moderados transitivos nas ferramentas de teste/
  deploy (firebase-tools); não fazem parte dos módulos Firebase servidos no app.
  Não foi aplicado downgrade incompatível sugerido por `audit fix --force`.
- Política definitiva e confirmação do responsável seguem para Fase 4.
- Publicação autorizada pelo usuário após testes; resultado remoto registrado
  depois da execução do workflow e da conferência da Vercel.
